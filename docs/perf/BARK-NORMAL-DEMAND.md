# Generate bark normals only when requested

Published fixture: [0.0.18 · 421d34b](https://ael-dev3.github.io/Tervain/). Related foliage/load work: [playtest checklist](https://github.com/ael-dev3/Tervain/issues/326).

The metre-scale bark detail installed on imported trees reads only the generated colour and relief/roughness textures. `barkTextures` nevertheless also converted the height field into a separate normal map. At 1024² that visits 1,048,576 texels, including a three-component `Math.hypot` per texel, even when no material reads the result.

The normal texture is now generated on its first explicit request and cached. Its conversion and texture settings are unchanged. Disposal releases an already-generated normal without creating an unused one. The 256px normal maps used by procedural wood still generate when that material requests them.

## Matched software receipt

The live Low-profile fixture identifies **oak and pine** 1024px detail pairs in the native forest materials.

| Check | Original | Candidate |
| --- | ---: | ---: |
| Normal conversion texels for that observed detail-kind set | 2,097,152 | 0 |
| Unrequested 32² normal generated before disposal | 1,024 texels | 0 |
| Normal texels generated by disposal | 0 | 0 |
| Native draw calls | 47 | 47 |
| Native triangles | 196,106 | 196,106 |
| Changed pixel channels | — | 0 |

All colour, surface and explicitly requested normal hashes match for **oak, pine and dead** bark. The explicit request still performs exactly 1,048,576 conversion texels per 1024² map, once. Dead bark is a generator compatibility check here, not part of the observed native-kind work total.

[Matched receipt](proofs/bark-normal-demand/report.json) · [Original](proofs/bark-normal-demand/before.png) · [Candidate](proofs/bark-normal-demand/after.png) · [Unchanged-source control](proofs/bark-normal-demand/control.json)

The replay identifies the actual native detail texture kinds by matching their colour **and** surface bytes against the source generator. It then renders the same isolated native oak wood geometry, placement and material hook with the original and candidate detail textures through the native post/MSAA path. Explicitly requested normal-map bytes are compared separately for oak, pine and dead bark. The source instrument counts visits to `heightToNormal`; it does not estimate hardware frame times.

This is a loading-work reduction, not a canopy-quality fix or a claim that historical frame spikes are gone. No normal-map GPU upload saving is claimed: the unused normal was not uploaded by these detail materials. Unrequested normals retain the original Float32 height field instead of RGBA normal bytes, so this receipt also makes **no net retained-heap saving claim**. Callers that explicitly request a normal retain its conversion cost.

## Reproduce

```sh
node tools/repro-live-bark-normal-work.mjs --out bark-normal-proof
node tools/repro-live-bark-normal-work.mjs --candidate-ref 7169afa41 --out bark-normal-control
```

The first command must pass; the unchanged-source control must fail. Both default to the published Pages build and software WebGL at Low, 640×360. Generated normal, colour and surface hashes must match; the native capture must have zero changed channels.

Validation: 22 relevant tests pass, including the regression that fails on the original source with 1,024 unnecessary normal-generation calls at 32², plus requested-normal caching and disposal. Production build/type check passes. Hardware play-gate remains pending.
